# Mobile Release Build (sideloadable signed APK)

How to produce a **release-signed, sideloadable Android APK** of the mobile app
using a **local keystore**. This is the free, local, no-cloud path: no Expo cloud
build, no Google Play account, no Store submission.

!!! note "CI attaches a release-signed APK to every release"
    The [`Mobile APK`](../../.github/workflows/mobile-apk.yml) workflow builds
    `bike-trip-planner.apk` (`expo prebuild` + `./gradlew assembleRelease`) and
    attaches it to each published GitHub Release (or to an existing release tag via a
    manual `workflow_dispatch`). It is signed with the **private release keystore**
    stored in the `release` GitHub Environment (see [CI signing](#ci-signing) below),
    and the job fails if those secrets are missing: it never falls back to the
    public debug keystore. Follow the procedure below to build the same kind of APK
    locally.

## CI signing

`mobile/android` is generated by Expo CNG, so the release `signingConfig` is injected
at prebuild time by the [`withReleaseSigning`](../../mobile/plugins/withReleaseSigning.js)
config plugin. It reads the keystore at Gradle time from four env vars:

| Env var | Content |
|---|---|
| `ANDROID_KEYSTORE_PATH` | Path to the keystore file (CI decodes it into `$RUNNER_TEMP`) |
| `ANDROID_KEYSTORE_PASSWORD` | Store password |
| `ANDROID_KEY_ALIAS` | Key alias (`btp-release`) |
| `ANDROID_KEY_PASSWORD` | Key password |

Without `ANDROID_KEYSTORE_PATH` a local `assembleRelease` keeps the template's debug
signing, so dev builds need no secret. The CI job refuses to build without the
secrets, then checks with `apksigner` that the APK's signer is the keystore's
certificate and not the debug one.

### One-time setup

1. Generate the release keystore (step 1 of the [procedure](#procedure)) on a trusted
   workstation and store it, with both passwords, in the team password manager.
2. In the repository settings, create an Environment named **`release`**. Restrict
   its deployment branches and tags to `main` (the ref of a `workflow_dispatch` run) and
   `v*` (the ref of a `release` run), and add the owner as a required reviewer, so the
   keystore secrets are only readable by an approved release run.
3. Add the environment secrets:

    ```bash
    base64 -w0 release.keystore | gh secret set ANDROID_KEYSTORE_BASE64 --env release
    gh secret set ANDROID_KEYSTORE_PASSWORD --env release
    gh secret set ANDROID_KEY_ALIAS --env release      # btp-release
    gh secret set ANDROID_KEY_PASSWORD --env release
    ```

4. Point App Links at the new key. Take the fingerprint
   (`keytool -list -v -keystore release.keystore -alias btp-release | grep SHA256`)
   and set it as `android_sha256_cert_fingerprints` in `ansible/group_vars/all.yml`
   (it is public; the debug fingerprint must be **replaced**, not kept next to it).
   The `app_deploy` role refuses a placeholder or the debug fingerprint. Re-run the
   playbook, then `btp-compose up -d` on the VM to recreate `pwa`; no image rebuild is
   needed, the route reads the variables at runtime.
5. Re-run `Mobile APK` (`workflow_dispatch` with the current tag) to publish a
   release-signed APK.

### Testers: reinstall once

Android refuses to upgrade an installed app with an APK signed by a different key.
Every tester who installed a previous debug-signed APK must **uninstall** it once
(this wipes the session and the offline cache), then install the new APK and sign
in again. Later releases signed with the same keystore upgrade in place.

## When to use

- You need a standalone APK to install on a real device or hand to a tester.
- The APK must be **release-signed** (a debug/dev-client build is not enough).
- You explicitly do **not** want Store distribution this sprint.

## Diagnosis

The mobile app is an **Expo CNG project**: `mobile/android` is generated by
`expo prebuild` and is gitignored (see `mobile/.gitignore`). There is therefore no
committed `android/app/build.gradle` to edit in place. Locally, release signing is
wired through EAS local credentials (`eas.json` + `credentials.json`), which EAS injects
into the generated Gradle `signingConfig` at build time. CI (and the raw-Gradle path in
the appendix) uses the env-driven `signingConfig` of the `withReleaseSigning` plugin
instead.

Prerequisites (same as `mobile/README.md`):

- Node 20+ and npm, JDK 17
- Android SDK (`adb` on `PATH`), a device with USB debugging or an emulator
- `EXPO_PUBLIC_API_URL` set to an HTTPS host reachable **from the phone** (the
  value is inlined into the JS bundle at build time; a non-dev build fails closed
  without it)

## Procedure

### 1. Generate the local keystore (once)

Never commit this file. Keep it and its passwords somewhere safe (a password
manager) — losing it means you can never ship an update that upgrades a previously
installed APK in place.

```bash
cd mobile
keytool -genkeypair -v \
  -keystore release.keystore \
  -alias btp-release \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass '<STORE_PASSWORD>' -keypass '<KEY_PASSWORD>' \
  -dname 'CN=Bike Trip Planner, O=les-tilleuls.coop, C=FR'
```

This writes `mobile/release.keystore`, which is gitignored (`*.keystore`).

### 2. Declare the keystore to EAS (`credentials.json`)

Create `mobile/credentials.json` (gitignored — it holds the passwords):

```json
{
  "android": {
    "keystore": {
      "keystorePath": "release.keystore",
      "keystorePassword": "<STORE_PASSWORD>",
      "keyAlias": "btp-release",
      "keyPassword": "<KEY_PASSWORD>"
    }
  }
}
```

`keystorePath` is relative to `mobile/`. The `release` profile in
[`eas.json`](../../mobile/eas.json) sets `credentialsSource: local`, so EAS reads
this file instead of prompting for or storing credentials in the cloud.

### 3. Build the signed release APK

```bash
cd mobile
EXPO_PUBLIC_API_URL=https://<api-host> \
  npm run build:release
# -> npx eas-cli build --local --platform android --profile release
# -> writes a release-signed APK such as build-<timestamp>.apk in mobile/
```

The build runs entirely on your machine (`--local`). No cloud build is submitted.

### 4. Sideload onto a device

```bash
adb install -r build-<timestamp>.apk   # USB debugging enabled, device authorised
# or copy the .apk to the phone and open it (allow "install unknown apps")
```

Verify the signing certificate if needed:

```bash
keytool -list -v -keystore release.keystore -alias btp-release | grep SHA256
```

## Verification and follow-up

- Store `release.keystore` and its passwords in the team password manager. The same
  keystore MUST be reused for every future update of the same `package`
  (`coop.lestilleuls.biketripplanner`); a different key forces an uninstall/reinstall.
- Bump `android.versionCode` (and `version` when user-facing) in
  [`mobile/app.json`](../../mobile/app.json) before each new build you distribute —
  Android refuses to upgrade in place over an equal-or-lower `versionCode`.

## Out of scope (deferred)

The following are **intentionally not covered** this sprint:

- **Google Play / Store distribution** — no Play account, no App Bundle upload, no
  managed Play signing. The `production` profile in `eas.json` (`app-bundle`) exists
  for that future path but is not exercised here.

## Appendix - raw Gradle path (optional)

If you prefer building through Gradle directly instead of `eas build --local`, export
the env vars of [CI signing](#ci-signing) and run the same commands as CI. The plugin
re-applies on every `expo prebuild`, `--clean` included.

```bash
cd mobile
EXPO_PUBLIC_API_URL=https://<api-host> npx expo prebuild --platform android --no-install
cd android
ANDROID_KEYSTORE_PATH="$PWD/../release.keystore" \
ANDROID_KEYSTORE_PASSWORD='<STORE_PASSWORD>' \
ANDROID_KEY_ALIAS=btp-release \
ANDROID_KEY_PASSWORD='<KEY_PASSWORD>' \
  ./gradlew assembleRelease
# -> app/build/outputs/apk/release/app-release.apk
adb install -r app/build/outputs/apk/release/app-release.apk
```
